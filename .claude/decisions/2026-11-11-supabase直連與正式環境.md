# 2026-11-11 Supabase 直連、正式環境與發版流程

## 背景

2026-07-24 定的方向是自建 Go REST API + SQLite + Litestream,同步協定為 updatedAt 增量拉推 + LWW + 刪除墓碑。2026-11-10 Mike 裁示改用 Supabase(與記帳 app 同一套),並把 Flutter 版轉 /mvp 加速。2026-11-11 Flutter 版第一次連正式環境發 TestFlight,接管已上架 iOS app 的真實使用者資料,/mvp 畢業。以下是 MVP 期間累積、日後不看脈絡會覺得奇怪的決定。

## 選項

1. 離線優先:本機 Drift 為主,背景與 Supabase 雙向同步(原 07-24 協定換後端)。
2. 直連:資料讀寫直接走 Supabase,本機 Drift 只當舊資料匯入落點、上傳來源與測試假件。

## 選擇

選 2,外加以下配套:

- 進行中的訓練草稿存本機,完成時一次上傳(健身房網路差,記到一半不能掉);其他功能沒網路就不能用。
- 舊 iOS CoreData 首啟先匯入本機 Drift,登入後一次性上傳到登入者帳號;上傳只認本機 owner 等於登入者的資料。
- 環境分兩個專案:`workout-dev`(開發、debug build)與 `workout-prod`(TestFlight/App Store,ap-northeast-1)。release build 沒帶連線設定就拒絕啟動,打包只走 `app/tool/build_ios_prod.sh`,腳本會檢查產物帶的是 prod 而不是 dev。
- 刪帳號走 RPC `delete_my_account`(security definer,cascade 全部資料),並撤銷 Sign in with Apple 授權(Edge Function `apple-revoke`,.p8 只存在 Supabase secrets),同時刪除裝置上舊 iOS 留下的 CoreData 檔(Mike 2026-11-11 裁示)。
- 動作引用限「系統動作或本人動作」(migration 0600),避免別人的引用卡死刪帳號。

## 理由

- 直連省掉同步協定(衝突解決、墓碑、時鐘偏差)整層複雜度;兩人以下規模的個人 App,離線記錄只在訓練中真正需要,草稿本機化就涵蓋。
- 同一套做法已在記帳 app 驗證過(TestFlight 連 prod、API 金鑰上傳)。
- 正式環境分離加上產物閘,是畢業總審 B1 的修法:漏帶設定時若默默連 dev,真實用戶的舊歷史會被傳到 dev,改發正確版本後還會因 owner 不符被清掉本機資料。
- 代價:沒網路不能看歷史與統計;Google 登入暫緩,Web/Android 雲端模式暫無登入入口。
