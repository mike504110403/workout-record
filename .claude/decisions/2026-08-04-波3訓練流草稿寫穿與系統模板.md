# 波 3 訓練流:進行中訓練採 Drift 草稿寫穿 + 種系統模板(2026-08-04)

## 背景

波 3(記訓練核心流)探路發現兩處 iOS 基準不宜照抄:(1) iOS 進行中訓練是純記憶體(ViewModel),App 被殺即丟、無恢復——web 平台「重新整理」比 iOS 被殺頻繁得多,照抄會讓丟訓練變常態;(2) iOS 的五個系統模板(PPL-Push/Pull/Legs、上肢、全身)只存在 DEBUG mock 段,release 使用者看不到。

## 選項

- 持久化 A:對等 iOS 純記憶體 / **B:Drift 草稿寫穿**(Workouts.endedAt 本就 nullable,endedAt=NULL 即進行中;每加動作/組即入庫;啟動偵測未完成訓練詢問恢復或放棄)。
- 系統模板 A:不種(對等 release)/ **B:把 iOS DEBUG mock 的五個模板轉正式種子**。

## 選擇

**兩項皆 B(Mike 2026-08-04 拍板)**;波次拆法採兩段式:①動作選擇器 + ③模板管理平行 → merge → ②訓練核心流。

- 草稿寫穿代價是 History/Dashboard 查詢須排除 `endedAt IS NULL`、放棄訓練須刪草稿列;換到三平台一致的抗丟失。

- 選動作器契約(段間接縫):`Future<List<Exercise>?> showExercisePicker(BuildContext, {bool multiSelect = false})`,①實作;③第一段以同簽名 fake 頂替,merge 時由大腦接線。
