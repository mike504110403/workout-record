# 2026-07-24 三平台(iOS/Android/Web)+ 雲端同步方向

## 背景

Mike 新增需求:web 也要完整功能、同帳號跨裝置同步、三平台一起首發。
這推翻 2026-07-22 kickoff 的兩個前提:「第一版不接 Firebase/雲端」「資料只存裝置本機」。
同時確立開發順序鐵律:**依使用者操作順序做 UI 垂直切片,每波都能在模擬器/瀏覽器看到進度,後端/同步不排在前面**;全部決策定案前不動工實作。

## 已定決策

### 1. 帳號系統:Apple + Google 雙登入
- 現有 iOS 用戶無縫延續 Sign in with Apple;Android/Web 用戶用 Google 最順。
- Apple 審核規則:iOS 上提供第三方登入(Google)就必須同時提供 Sign in with Apple → 雙登入合規。
- 代價:兩套 OAuth 設定都要辦;web/Android 的 Apple 登入需另辦 Services ID + .p8 憑證走 redirect flow。
- 落選:只做 Apple(Android/Web 體驗差)、Apple + Email OTP(體驗陽春)。

### 2. 隱私政策改版時機:掛同步那一波再改
- 現行文案(Onboarding/About/privacy.html/App Store 隱私標籤)全寫「資料只存裝置本機」;UI-first 純本機階段這仍是事實。
- 等同步功能真的進來前,一次性改齊文案 + 隱私頁 + 商店標籤,避免改兩次。
- **硬性檢核:掛同步波的驗收清單必含隱私改版,漏了不得上架。**

### 3. 社群 skill:裝 flutter-tester + owasp-mobile-security-checker
- 來源 Harishwarrior/flutter-claude-skills;大腦逐檔安全審閱通過(四支 Python 掃描器皆本地分析、無網路連線,唯一 subprocess 是 `flutter pub outdated --json`)。
- 落選:Project Initializer(scaffold 已建,零價值)、Play Store Deploy(碰 Google 憑證且離 Android 上架遠,第二波再評)、教學型架構 skill(價值低)。

### 4. 同步架構:完全自建後端(Go + SQLite + Litestream)+ 自寫簡易同步
- **同步協定**:updatedAt 時間戳增量拉推 + 後寫勝(LWW per row)+ 刪除墓碑;不做即時推播。單人帳號、衝突僅發生於同一人多裝置、數千筆量級,此協定足夠。
- **後端**:Go REST API + SQLite 單檔 + Litestream 自動備份到 S3 相容儲存;部署在 Mike 現有伺服器(Docker/systemd 與 web 靜態檔供應細節留到掛同步波)。
- **Drift 資料層 100% 保留**,FK/cascade/index 全部照舊生效;UI-first 完全相容(掛同步波之前後端一行都不用寫)。
- **Mike 選自建的動機**(壓測過):本身有後端能力與現成伺服器、不想被第三方廠商綁、長期成本與資料主權。
- 落選:
  - **Supabase + PowerSync**:深挖(powersync-deep-dive)證實技術可行但代價高——雙 schema 對照表、client 表是 View 導致 NOT NULL/FK/cascade/index 全流失需 app 層+後端兩邊補、cascade 改手寫、且被 Flutter 3.38.5 的 meta 1.17.0 牆卡死(需升版才裝得上)。Mike 否決。
  - **Firebase/Firestore**:Drift 整層重寫、本機開發從第一天綁後端。
  - **Turso / ElectricSQL / Brick**:offline writes 未熟 / 只做讀路徑 / 要重寫資料層。

### 5. 升 Flutter:3.38.5 → 最新 stable(Dart ≥3.11)
- 與同步方案脫鉤後仍執行:解掉 meta 1.17.0 天花板連帶的所有降版妥協(drift 釘 2.31、放棄 drift_flutter、riverpod_generator 壓版)。
- 時機:codebase 還小(資料層 + 匯入器 + 骨架),升版代價最低;升完重訂依賴 pin 並重跑全部驗證。

### 尚未明朗(戰爭迷霧,掛同步波前再解)
- 同步 API 細部設計(endpoint、墓碑表結構、增量游標)——工程設計,掛同步波前出設計文件
- 部署細節:哪台伺服器、Docker vs systemd、網域/TLS、web 靜態檔供應
- Auth 實作細節:Apple/Google token 後端驗證、session 機制(安全敏感,實作時強制 security review)
