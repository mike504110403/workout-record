## 🚀 上架流程

### 步驟 1：Archive

1. 確認 Scheme 設為 **Release**
2. 選擇 **Generic iOS Device**（Any iOS Device）
3. Product → Archive
4. 等待 Archive 完成

### 步驟 2：上傳到 App Store Connect

1. 在 Organizer 中選擇剛建立的 Archive
2. 點擊 **Distribute App**
3. 選擇 **App Store Connect**
4. 選擇 **Upload**
5. 保持預設設定（Automatically manage signing）
6. 檢查 App 資訊
7. 點擊 **Upload**
8. 等待上傳完成

### 步驟 3：等待處理

1. 上傳後需要等待 Apple 處理（通常 5-30 分鐘）
2. 收到郵件通知「已準備好可供測試」
3. 前往 App Store Connect → TestFlight

### 步驟 4：TestFlight 測試

1. 在 TestFlight 中啟用新版本
2. 填寫測試說明（給測試者看的）
3. 邀請測試者或自己先測試
4. 確認所有功能正常

### 步驟 5：提交審核

1. 確認 TestFlight 測試通過
2. 前往「發佈」頁面
3. 選擇要發佈的版本
4. 填寫版本更新說明
5. 選擇發布方式：
   - 手動發布（推薦）
   - 自動發布
6. 提交審核
7. 等待審核結果（通常 1-3 天）

## ⚠️ 常見問題預防

### 問題 1：Archive 失敗
**檢查：**
- 是否選擇了「Generic iOS Device」
- 簽章設定是否正確
- 是否有編譯錯誤

### 問題 2：上傳被拒
**檢查：**
- 版本號是否大於上一版
- Bundle ID 是否正確
- 簽章憑證是否有效

### 問題 3：審核被拒
**常見原因：**
- 隱私權設定不完整
- 功能描述不清楚
- App 崩潰或嚴重 Bug
- 違反 App Store 規則

### 問題 4：Firebase 連線失敗
**檢查：**
- GoogleService-Info.plist 是否正確
- 安全規則是否正確設定
- 網路權限是否正常
